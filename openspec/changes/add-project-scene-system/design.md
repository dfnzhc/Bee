# Design

## Context

变更动机见 [proposal.md](proposal.md)。目前 `main.rs` 直接创建使用 `SceneState::default()` 的工作台，`FlowEditor` 持有草稿和生效图，`Files` 已在后台读取目录并按请求代际接收结果。视口使用共享的 `RenderSnapshot` 与有界渲染队列。项目生命周期和磁盘读写接入 `crates/bee`，场景数据和渲染仍由现有层负责。

## Goals / Non-Goals

**Goals**

- 在应用层管理单个项目和单个活动场景，通过现有场景快照接口驱动视口。
- 将磁盘内容、运行时视角和设备实际执行的流程分别管理，使场景可迁移、可验证、可恢复。

**Non-Goals**

- 资源导入与索引、跨项目引用、多个场景同时编辑、场景对象编辑。

## Decisions

### 1. 项目清单与独立场景文件

```text
ProjectRoot/
|-- project.beeproj
|-- Scenes/
|   `-- <scene-id>.beescene
`-- Assets/
```

项目清单和场景文件使用带 `format_version` 的 UTF-8 JSON。清单保存项目 UUID、显示名称、场景 UUID 与名称列表以及启动场景 UUID。场景文件通过 UUID 推导项目内相对位置，文件内含同一场景 UUID。可见名称放在清单中，改名只需提交清单，两个场景各自可以独立保存。

场景文档存储当前数据模型的网格、实例、材质、灯光、环境、起始相机和渲染参数，以及第 2 项定义的流程数据。示例模板从 `Scene::builtin()` 生成一次并落盘。空白模板使用有效相机和环境，四类场景数据集合均为空。最近项目使用 Bee 的本机用户设置，记录项目标识、名称和目录，成功打开后更新。

打开时先检查版本，再检查标识唯一性、启动场景登记、场景标识、引用索引、有限数值、变换、相机及渲染参数。路径使用解析后的项目目录和固定子目录验证，拒绝越出项目边界的目录联接及符号链接。读取其他场景的具体内容延迟到其被打开、复制或恢复时，以便单个损坏的场景可单独处理。

### 2. 场景文档与实时预览

场景文件存储 Render Flow 的节点、参数和连接，分别表示草稿和最后一次成功应用的流程。加载时通过现有 `ModuleGraph` 验证结构与引用。已应用流程须能通过执行前验证，草稿允许缺失连接或其他尚未可执行的状态。曝光以色调映射节点参数为准。`PreparedFlow`、Vulkan 资源、帧及版本计数均由本次会话产生。

调用现有流程准备逻辑生成设备可执行的计划。已应用流程如果在本机缺少光追能力，使用保留曝光的临时光栅预览，界面显示实际运行模式和原因。保存依据文档中的已应用配置和草稿，用户显式应用新流程时更新已应用配置。

滚动和拖动更新运行时视角。用户选择「将当前视角设为起始视角」时复制当前相机到文档。文档内容、流程编辑及应用参与未保存判定，场景树选择和布局操作只更新界面状态。

### 3. 写入顺序和恢复

| 操作 | 写入及提交顺序 |
| --- | --- |
| 新建项目 | 校验目标新目录或显式选择的空目录，创建首个场景与 `Assets/`，最后提交项目清单。失败时只清理本次创建的条目。 |
| 新建或复制场景 | 创建新的 UUID 和独立文件，再提交包含新场景的清单。复制基于来源场景已保存的文档。 |
| 改名或设为启动场景 | 提交项目清单，成功后更新内存列表。 |
| 删除场景 | 确认项目仍有其他场景，并先准备必要的当前场景和启动场景替代项。提交更新后的清单，再将原场景文件移入项目内的恢复目录。若移动失败，报告原文件的保留位置。 |
| 保存场景 | 核验磁盘文件仍匹配已加载或已提交的内容，写完同目录临时文件并刷新。保留上一份有效文件的备份后，使用 Windows 支持的同目录文件替换操作提交正式版本。 |
| 恢复场景 | 校验备份的版本、内容和场景标识，用户确认后安全提交为该场景的正式文件，保留可用备份。 |

清单更新复用同目录安全提交。创建新文件使用独占创建或不覆盖的提交方式。项目写操作按项目根串行，在核验和提交之间持有同项目的进程间写入保护，使用可随进程退出释放的锁。遇到外部修改或其他写入占用时保留原文件。临时文件与场景备份可用固定后缀区分，正式场景以项目清单和稳定路径为准。

### 4. 先准备目标再切换工作台

启动页和工作台复用目录选择及项目读取逻辑。应用先准备目标项目和场景，再处理当前场景的未保存内容，最后在同一次界面状态更新中替换项目标识、场景文档、`SceneState`、流程和选择状态。新建或删除当前场景也使用相同的离开确认。保存或加载失败时保留工作台，选择放弃时仍等切换可提交后再释放旧文档。保存完成时仅清除已写入版本的未保存状态。

窗口关闭和 `File > Exit` 共用未保存确认，再走现有渲染队列停止与资源清理流程。关闭项目清理项目会话并回到选择页。启动场景无法加载时，可从该项目清单选择其他可用场景或恢复上一份场景备份。

`Files` 将当前项目的 `Assets/` 设为项目浏览的边界，`Browse Folder…` 进入显式外部浏览，返回项目资源的入口切回根目录。同项目切换场景保留当前位置。切换项目时重置根目录，并作废之前的目录读取请求与文件夹选择请求。默认抽屉布局沿用现有工作台设定。

### 5. 场景切换与空场景渲染

用视口已有的请求代际和历史代际区分场景切换。目标切换提交时清除可见旧帧、样本计数及累积历史，并提交新快照。以内容相同或初始版本号相同的两个场景验证该流程，确认旧帧仍无法覆盖新场景。旧资源遵循现有队列与呈现端的生命周期，兼容的执行计划继续复用。

现有光追测试清空场景实例，空白模板还需覆盖零网格、零材质和零灯光。使用真正的空文档走 `RasterScene` 与 `PathScene`，检查清屏、空资源绑定和背景输出。通过现有场景缓冲和空绘制逻辑完成空输入，在测试暴露缺口的层修正。

## Risks / Trade-offs

- Windows 提交中断或失败可能发生在备份和正式文件替换之间。用子进程在可控写入阶段中断，重开并验证对应的完整正式版本或备份。硬件断电后的持久性需要独立验证。
- 场景清单和独立文件是多个目录项。创建以清单为可见提交点，删除先提交清单再回收文件，提交失败或中断时仍保留可定位的完整文件。
- 生成背景画面和接收旧帧属于不同的验收路径。用延迟帧测试覆盖切换边界，用开启验证层的可用 Vulkan 设备验收两条渲染路径的真正空场景。

## Migration Plan

首次发布从版本 1 的文件格式开始。原内置场景通过示例模板生成真实项目文件。项目整体复制或移动后从新目录打开。旧版 Bee 可继续独立运行其内置场景，项目文件保留供支持这些格式的版本使用。
