# Proposal

## Why

项目尚无渲染器实现，需要先建立一个能够运行、验证和继续扩展的基础框架。第一版以 Windows 上的交互式三维渲染为核心，同时支持光栅化与路径追踪，并为后续组合渲染算法留出清晰边界。

## What Changes

- 建立 Rust 应用、自研 Vulkan 图形接口封装和 GPUI 编辑器。GPUI 负责自身界面绘制，所有三维场景画面由自研 Vulkan 渲染器生成。
- 提供同一场景下可切换的实时光栅化与路径追踪路径；路径追踪支持静止时逐帧累积，运动期间允许明显噪点。
- 提供算法模块级的可视化渲染流程编辑：以光栅化、路径追踪、色调映射和输出为初始模块，连接关系驱动渲染图执行。
- 建立渲染图对资源依赖、资源生命周期和同步的基础管理，允许将来的渲染算法组合；第一版不要求光栅化与路径追踪融合。
- 验证 Vulkan 场景画面在 GPUI 视口中的接入，并在共享纹理不可用时提供明确标识的可用展示路径。
- 提供最小内置场景、相机交互、能力检测和必要的诊断，形成可以实际运行和验证的端到端框架。
- 不设固定帧率或其他性能数值验收门槛；框架稳定或发现瓶颈后再建立基线并优化。

## Capabilities

### New Capabilities

- `vulkan-backend`: 初始化和使用自研 Vulkan 图形后端，报告图形和光追能力与错误。
- `interactive-viewport`: 在 GPUI 应用中展示自研渲染器的画面，并提供共享场景和相机交互。
- `render-graph`: 编辑和验证算法模块连接，并按照资源依赖执行渲染流程。
- `raster-rendering`: 对共享场景执行交互式光栅化渲染。
- `path-tracing`: 对共享场景执行实时路径追踪和渐进累积。

### Modified Capabilities

无。

## Impact

- 新建 Rust 工作区、Windows 桌面应用、自研 Vulkan 后端、场景数据、渲染图和两种算法模块。
- 引入 GPUI、Vulkan 的 Rust 绑定及必要的窗口、着色器和构建依赖；GPUI 的界面绘制后端与场景渲染后端保持独立。
- Windows 上需要可用的 Vulkan 驱动；路径追踪还需要相应硬件及驱动能力。GPUI 与 Vulkan 之间的高效纹理共享尚待验证，实际接入方式可能需要适配 GPUI。
- 暂不交付其他图形 API 后端、离线高质量出图、实时降噪、混合渲染、复杂资产管线或通用插件系统。
