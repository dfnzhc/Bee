# Design

## Context

`Workbench` 使用 GPUI 的 `DockArea` 管理六个面板，`reset` 目前创建始终占用高度的底部分区。`Viewport` 根据实际画布和系统缩放申请渲染尺寸，并通过异步读回显示 Vulkan 画面。设备初始化报告已进入 `Console`，当前画面接入方式则显示在视口状态条。

## Goals / Non-Goals

工作台负责菜单、停靠布局、抽屉和焦点。现有的面板实体继续承载只读场景检查、文件浏览、诊断与流程编辑。场景和项目命令的设计留给后续变更。

## Decisions

### 在现有工作台接入应用菜单

复用 `PopupMenu`、现有焦点管理和面板访问逻辑，把菜单分别锚定到 `File` 和 `View`。`View` 将焦点交给打开的面板，取消菜单时将焦点交回对应触发按钮。`Exit` 与原生关窗共用 `Viewport::request_close` 的关闭流程，最后一个窗口在在途渲染工作完成并释放资源后关闭。

### 在现有停靠体系内收起底部区域

将底部入口保留在停靠内容之外，由 `Workbench` 管理底部停靠区的开合和当前标签。入口激活已有面板，关闭过的面板复用现有实体恢复。面板拖到别处后，入口定位到当前停靠位置。收起只改变底部区域的参与布局状态，重置复用现有的布局重建逻辑和面板实体。

按样稿以约 `200` 和 `220` 逻辑像素作为左、右栏的起点，小窗口优先给视口留出空间。压缩标题栏、行高和内边距，统一深色面板分隔线、选中和焦点样式。

### 用画布的真实尺寸显示画面

把渲染选项和光追样本数排进同一行，去掉画布外的内边距。`Viewport` 继续用实际画布边界和系统缩放计算渲染尺寸。底部开合或分区缩放改变实际尺寸时，沿用现有的重设尺寸及过期帧处理。仅切换焦点且画布尺寸一致时，保留当前采样。

复用现有诊断通道报告画面接入方式，在接入方式确定或变化时记录。视口保留设备不支持光追、渲染失败或流程应用失败的简短提示，详细原因由现有就地信息或 `Console` 提供。

## Risks / Trade-offs

- [抽屉收起后面板访问或焦点失效] → 覆盖底部入口、`View`、拖动停靠和重新打开，检查同一面板只出现一次。
- [布局变化时显示过期帧] → 用现有尺寸、可见性和代次判断过滤旧结果，覆盖连续开合、隐藏和恢复。
- [缩放后单行控件放不下] → 用 `960 × 640` 和 Windows 系统缩放复核控件边界与键盘可达性。

## Migration Plan

先落地菜单和停靠布局，再调整视口呈现，最后更新使用文档和回归测试。布局变更随应用发布，回退时恢复上一版工作台。归并本增量之前，先同步 `editor-ui-workbench` 的 `editor-workbench` 规格基线。
