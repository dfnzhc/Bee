# Tasks

第 1–3 组是首批交付。完成 3.4 的同条件对照后，再推进第 4–5 组。

## 1. 性能基线

- [x] 1.1 为两条路径添加按帧关联的 CPU 阶段耗时、GPU pass 时间戳和图编译、管线创建、网格上传、加速结构操作计数。用短序列采样核对计数及耗时能对应到正确的模式、相机版本和帧。
- [x] 1.2 提供停靠工作台、独立视口和仅渲染的可重复采样方式，记录 Windows Release 下的基线及运行命令。三组使用相同物理分辨率和输入序列，光追固定样本数与反弹数。核对可见组能报告 GPUI 上传、原生输入到呈现 `p95`、输入合并比例及最终视角延迟。

## 2. 执行计划与资源复用

- [x] 2.1 验证并编译生效流程的可达工作，缓存执行计划，在候选计划准备成功后替换。用编译计数覆盖相机、实例参数、曝光及兼容尺寸变化，并验证拓扑变化会选用新计划、无效草稿保留当前计划。
- [x] 2.2 将逻辑资源与帧绑定分离，在提交时应用真实的初始用途、布局和必要同步。扩展渲染图测试，覆盖同一计划多次执行、替换目标后执行，以及 Vulkan 验证层下的资源依赖和生命周期。
- [x] 2.3 复用管线、兼容的目标和读回资源，按场景版本常驻光栅几何缓冲区。热身后对两种模式连续更新相机，验证不再创建管线、上传静态网格或构建及更新 BLAS/TLAS。
- [x] 2.4 让光追复用首样本及续采执行计划。验证运动和尺寸变化从首样本开始，静止时按顺序累积，同一组数据变化不会触发图编译。

## 3. 有界异步交帧

- [x] 3.1 用可复用帧槽和 GPU 完成信号推进渲染及读回，空闲时取最新输入。用延迟消费测试验证有空槽即可启动下一帧、在途帧数受限，且连续输入停止后最终视角自动送达。
- [x] 3.2 合并色调映射输出与读回源，直接传递紧密 BGRA 像素。用像素测试覆盖直接输出和格式转换回退，核对通道顺序、行跨度和颜色空间，并用计数确认移除了中间图像复制与重复打包。
- [x] 3.3 让工作台按需消费完成帧和渲染状态。扩展停靠拖动、乱序结果、尺寸切换、隐藏恢复、流程切换和关闭用例，验证画面不回退、资源安全退役，且面板操作不额外触发场景渲染。
- [x] 3.4 在 RTX 4060 Laptop 上按第 1 组条件复测，包含一组全屏物理分辨率。提交首批前后对照，逐项核对热身后重建计数为零、输入负载下的帧槽上限和最终视角，并报告两条路径的 `p95` 变化及剩余耗时来源。

## 4. 场景增量更新

- [x] 4.1 将光栅网格保留在对象空间，按网格、实例、材质和灯光区分更新。用共享网格多实例测试验证变换后的几何与法线，并核对模型移动时计划和网格缓冲区均被复用。
- [x] 4.2 为光追建立每网格 BLAS 和实例化 TLAS，支持按构建条件更新或重建 TLAS。用 GPU 用例验证单个实例移动、局部网格替换、仅材质或灯光变化时的画面、加速结构计数和累积重置。
- [x] 4.3 对仍有效的 HDR 结果执行纯曝光更新。用两条路径的输出测试确认亮度变化，同时验证该次显示更新未额外提交场景渲染或追踪采样，光追显示结果沿用对应样本数。

## 5. 自动调度与并行录制

- [ ] 5.1 补齐上传、加速结构构建、渲染及读回的资源声明，按实际生产和消费阶段生成 barrier。在 Vulkan 验证层下跑有依赖的绘制和追踪用例，验证写入对后续 GPU 工作可见。
- [ ] 5.2 保留编译后的 CPU 依赖关系，用常驻 Rayon 线程池执行有足够工作量的就绪任务。用受控分支测试验证独立工作重叠、后继按前置完成情况就绪，以及失败时不会提交部分录制结果。
- [ ] 5.3 用每帧槽、每工作线程的命令池并行录制，在单队列按计划提交。通过 `cargo test --workspace` 和适用的 Vulkan 验证用例，并在多绘制批次场景中同条件对比顺序和并行录制的耗时、画面及 `p95`，记录采用的任务粒度。

## Workflow follow-up

- 若首批数据表明读回和上传仍是主要延迟，验证 D3D11 创建共享纹理且由 Vulkan 导入的可行性，覆盖格式、适配器、同步和所有权。
- 执行图出现可重叠的 GPU 分支时，以同样的场景对照评估额外队列。
