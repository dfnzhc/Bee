# Spec Delta

## ADDED Requirements

### Requirement: 有界异步交帧

系统 SHALL 将视口的渲染、读回处理和呈现分开推进，并限制在途帧数。视口 SHALL 根据当前兼容性和已呈现进度选择画面，资源在所有使用者完成后方可回收。

#### Scenario: 呈现端尚未消费旧帧

- **WHEN** 旧帧正在进行读回后的处理或等待呈现，且新帧具备空闲帧槽及所需资源
- **THEN** 渲染端使用最新输入推进新帧，旧帧的交付独立完成

#### Scenario: 输入快于渲染

- **WHEN** 所有在途帧槽已占用且连续收到相机输入
- **THEN** 系统只保留最新待渲染状态，在帧槽可用后继续推进，保证最终视角得到呈现
- **AND** 较旧或不兼容的完成结果不得覆盖更新的已呈现状态

#### Scenario: 在途结果仍引用被替换的输出

- **WHEN** 视口调整尺寸、隐藏、切换流程或关闭，且旧输出仍被 GPU 或呈现端引用
- **THEN** 系统在旧输出的使用结束后回收它，并按当前视口状态接收后续结果

### Requirement: 工作台更新独立于场景渲染

与场景画面无关的面板更新 SHALL 与渲染请求独立，视口画面完成的通知 SHALL 限于消费画面和相关渲染状态的界面组件。

#### Scenario: 操作工作台面板

- **WHEN** 用户更改面板选择或可见性，且视口的尺寸、可绘制状态、相机、场景和生效流程都保持一致
- **THEN** 面板操作不增加场景渲染请求或重置光追累积

### Requirement: 提供可比较的视口性能诊断

系统 SHALL 支持在固定场景、物理分辨率和渲染参数下记录停靠工作台、独立视口及仅渲染配置的耗时和资源操作计数。

#### Scenario: 对照渲染与呈现成本

- **WHEN** 使用 Windows Release 构建运行性能对照
- **THEN** 结果报告各配置实际执行的 CPU 准备与录制、GPU 各阶段耗时和资源操作计数，并记录分辨率与光追采样参数
- **AND** 可呈现的配置还报告读回、像素处理、上传耗时和输入到呈现的 `p95` 延迟

#### Scenario: 热身后仅拖动相机

- **WHEN** 当前模式完成热身，且用户只移动相机，场景、视口物理尺寸和生效流程保持一致
- **THEN** 图编译、管线创建、静态网格上传以及加速结构构建或更新的计数增量均为零
