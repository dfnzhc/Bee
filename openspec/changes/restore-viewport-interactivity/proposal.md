# Proposal

## Why

当相机输入持续快于渲染完成时，Bee 的停靠视口在光栅化和路径追踪模式下都停留在操作前的画面。共享的交帧规则会丢弃尚未显示的中间相机帧，直到输入停止、最终帧与最新状态一致才更新画面。

## What Changes

- 在光栅化和路径追踪模式下，拖动过程中都用已完成的有效相机帧推动画面，并在等待下一帧时保留上一张可显示的图。
- 合并在途渲染期间的相机请求，输入停止后自动呈现最后一次输入对应的视角。
- 在视口尺寸、可见周期、场景、渲染参数或生效流程变化后，拒绝不兼容的在途结果。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `interactive-viewport` 明确两种渲染模式在持续操作期间、输入停止后以及视口状态变化时的画面呈现行为。

## Impact

- `crates/bee/src/viewport.rs` 中两种模式共用的输入处理、渲染调度与交帧，以及对应的 GPUI 回归测试。
- 路径追踪帧按现有 `path-tracing` 规范呈现。运动中的新视角允许低采样和噪点，静止后继续累积。
